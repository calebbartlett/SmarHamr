SmarHamr Workbench Documentation

SmarHamr Workbench is a tooling layer for inspecting, modifying, and validating Perchance Dexie exports. It focuses on structural integrity, safe automation, and asset-aware behavior (Tutor, characters, worlds).

1. Dexie Export Handling

1.1 Supported Format

The Workbench expects Dexie v1 exports with:

  • formatName = "dexie"
  • formatVersion = 1
  • databaseName = "chatbot-ui-v1"
  • databaseVersion = 90

1.2 Required Tables

The following tables must exist and be marked as inbound:

  • characters
  • threads
  • messages
  • misc
  • summaries
  • memories
  • lore
  • textEmbeddingCache
  • textCompressionCache

The validator checks:

  • Presence of each required table in both tables and data.
  • inbound: true on each data table.
  • rowCount in tables matches rows.length in data.

1.3 Row Count Synchronization

Before export or after structural changes, the Workbench runs a sync: 

meta.rowCount = dataEntry.rows.length;

This keeps Dexie metadata aligned with actual row arrays and prevents Perchance from misreading table sizes.

2. Workspace and File I/O

2.1 Loading Files

The Workbench supports:

  • Plain JSON exports.
  • Gzipped JSON exports (.json.gz), decompressed via pako.ungzip.

On load:

  • File is parsed into a JSON object.
  • Row counts are synchronized.
  • Dexie structure is validated.
  • Export is stored in window.smarhamrExport and localStorage.
  • The full JSON is rendered into a textarea for direct editing.

2.2 Live Editing

The main workspace is a textarea containing the entire export JSON. On input:

  • JSON is parsed back into an object.
  • Row counts are re-synced.
  • Validation is re-run.
  • Status line reflects success or JSON errors.

2.3 Exporting

The Workbench can export the current in-memory JSON as a one-line string, gzip it, and download it with a user-provided prefix: 

<prefix>.smarhamer.json.gz

3. SmarHamr Tutor

3.1 Purpose

The SmarHamr Tutor is a special character asset injected into the export to help users understand Perchance exports and the Workbench itself. It lives in the characters, threads, and messages tables.

3.2 Persona ID Namespace

Tutor and future SmarHamr personas use IDs in the 333xx range. The Workbench scans existing character IDs and picks the next available ID starting at 33300.

3.3 Tutor Bundle

The Tutor bundle consists of:

  • Character row — defines the Tutor persona.
  • Thread row — a dedicated Tutor thread.
  • Message row — an initial system-style message noting that the export was modified by SmarHamr.

The Tutor character includes:

  • name = "SmarHamr Tutor"
  • modelName = "perchance-ai"
  • fitMessagesInContextMethod = "summarizeOld"
  • textEmbeddingModelName = "Xenova/bge-base-en-v1.5"
  • An initial AI message linking to SmarHamr documentation.

3.4 Tutor Shortcut Bar

The Tutor has a dedicated shortcut bar designed for analysis and guidance: 

Explain  → /ai Explain this step-by-step.
Docs     → /ai Show SmarHamr documentation.
Inspect  → /ai Inspect this export and describe issues.
Validate → /ai Validate this export.

These shortcuts are attached to both:

  • characterRow.shortcutButtons
  • threadRow.shortcutButtons

This guarantees the shortcut bar appears when the Tutor is opened in Perchance.

4. Logic Engine

4.1 Purpose

The Logic Engine defines global “physics” and interaction rules for worlds and characters. It is stored as structured JSON inside the user role instruction field in the misc table.

4.2 Insertion Target

The Logic Engine is appended to the row: 

tableName: "misc"
key: "userRoleInstruction"

Existing user role text is preserved. The engine is appended below it.

4.3 Header Marker

The Workbench inserts a clear header above the JSON module: 

======== LOGIC ENGINE GOES HERE ========

4.4 Module Structure

The inserted JSON module has a structure similar to: 

{
  "logic_engine": {
    "spirals": ["Hand", "Hearth", "Shadow"],
    "pressure_levels": ["Soft", "Medium", "Hard"],
    "tethers": { "types": ["stabilizing", "destabilizing", "amplifying", "dampening"] },
    "state_elasticity": { "baseline_recovery": true, "collapse_vectors": true },
    "interaction_memory": { "emotional_residue": true, "behavioral_inertia": true },
    "environment_resonance": { "fields": ["ambient", "active", "overwhelming"] },
    "adaptive_thresholds": { "dynamic_spiral_limits": true }
  },
  "note": "This logic engine belongs in the USER ROLE. It defines global physics for all worlds and characters."
}

Users can extend or modify this JSON to define custom world logic.

5. Clean SmarHamr Profile

5.1 Purpose

The Workbench can generate a “clean” SmarHamr profile: a minimal Dexie export containing only:

  • One Tutor character.
  • One Tutor thread.
  • One Tutor message.
  • A basic misc table with user fields.
  • Empty summaries, memories, lore, textEmbeddingCache, textCompressionCache.

5.2 Usage

This clean profile can be exported and imported into Perchance as a starting point for SmarHamr-aware projects. It ensures:

  • Valid Dexie structure.
  • Presence of the Tutor.
  • Known baseline behavior.

6. Key Workbench Functions

6.1 File and Workspace

  • handleFileLoad(file): load, parse, sync, validate, render.
  • renderDexieWorkspace(data): show JSON in editable textarea.
  • exportGzipped(): export current JSON as gzipped one-line file.

6.2 Tutor

  • getNextPersonaId(): find next ID in the 333xx namespace.
  • buildSmarHamrTutorBundle(personaId): construct character, thread, and message rows with Tutor shortcuts.
  • onInsertSmarHamrTutor(): inject Tutor bundle into existing export.

6.3 Logic Engine

  • buildLogicEngineModule(): create the default logic engine JSON.
  • onInsertLogicEngine(): append header + JSON to misc.userRoleInstruction, preserving existing text.

6.4 Clean Profile

  • onLoadCleanSmarHamrProfile(): build a minimal export with the Tutor and basic tables, load it into the workspace, and sync row counts.

7. Future Extensions

The current implementation focuses on safe insertion and validation. Planned extensions include:

  • Separate shortcut presets for character assets and world assets.
  • Asset-type detection and automatic shortcut assignment.
  • Logic engine auto-mapping for renamed or missing fields.
  • World physics modules layered on top of the logic engine.
  • Deeper cockpit UI integration for asset management and testing.
